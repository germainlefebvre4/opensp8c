## Context

The application currently relies on default Tailwind CSS v4 colors with an alias mapping `slate` to `zinc` and `blue` to `emerald` in `frontend/src/index.css`. To provide a more professional, "pro tool" aesthetic, we want to adopt the Atlassian Design System (Jira) color palette.

## Goals / Non-Goals

**Goals:**
- Implement Atlassian Neutral (N10 -> N900) for Tailwind `slate` variables.
- Implement Atlassian Blue (B50 -> B500) for Tailwind `blue` variables.
- Ensure the application immediately reflects these colors globally across all UI components utilizing these Tailwind classes.

**Non-Goals:**
- We are not changing the structure or styling of React components.
- We are not introducing new CSS frameworks or component libraries.
- We are not altering other color palettes (e.g., semantic colors like red/green for statuses) in this specific change.

## Decisions

- **Tailwind Variable Overrides:** We will override the CSS custom properties generated by Tailwind v4 in `frontend/src/index.css`. 
  - *Rationale:* This is the least intrusive way to globally change the theme. Since the UI components are already built with Tailwind classes like `bg-blue-600` or `text-slate-800`, changing the underlying CSS variables will automatically theme the entire app.
  - *Alternatives:* Modifying Tailwind config directly (not ideal in Tailwind v4 which heavily relies on CSS variables and `@theme` directives), or refactoring components to use custom classes (too much effort, high risk of regressions).

## Risks / Trade-offs

- [Risk] **Contrast Issues:** Some Atlassian colors might not have the exact same contrast ratio as the original Tailwind colors they replace, potentially causing accessibility issues if used inappropriately.
  - *Mitigation:* We are mapping colors logically (e.g., N10 to slate-50, B400 to blue-500) to maintain structural visual hierarchy. Any specific contrast issues can be identified visually post-application.
